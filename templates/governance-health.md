## Claim coverage

Claim coverage: N/M (X%) backed by both · Told, not enforced: K

The fraction of governance claims backed by **both** an instruction and a gate (see
Definitions below), aggregated and trended here from **one fail-closed enumerator**.
Derivation contract — what the enumerator must do:

- **Sources:** `docs/definition-of-done.md`, `CLAUDE.md`, `docs/code-conventions.md`
  §1–§2. All three, or the run reports SKIPPED.
- **Claim:** a §1 table row, a §2 bullet, or — in the other sources — a bullet or
  numbered item carrying a normative keyword (must / never / always / required /
  shall).
- **Instruction-backed:** every claim, by construction (it is stated in an
  agent-readable instruction).
- **Gate-backed:** the claim names a backticked path that resolves to an existing
  file and is enforcement-shaped (a script, workflow, or test).
- **Fails closed:** any source absent, or yielding zero claims, reports SKIPPED
  naming the source — never a partial score. An enumerator that under-counts
  silently reports high coverage, and the metric becomes an imitation surface.

Two boundaries, both deliberate. The enumerator verifies the named gate *exists*;
whether it is *wired* is the audit's question (domain 8). And a claim stated nowhere
in the three sources — the true **neither** class — is invisible to this number by
construction: the metric names the instruction-only claims it can see; hunting
imitation surfaces beyond them is the audit's job, not this fraction's.

## Definitions — claims and backing

Every governance **claim** — a normative statement in a repo's governance
artifacts ("migrations squash at 50 increments", "every lint runs in CI",
"secrets live in the vault") — is backed by one or both of:

- **Instruction-backed** — an agent-readable instruction states the rule
  (CLAUDE.md, a policy doc, a skill). The claim is *told*.
- **Gate-backed** — a mechanical check enforces the rule (a lint, a CI gate, a
  required status check). The claim is *enforced*.

A claim backed by **both** is governed: told and enforced. A claim backed by
**neither** is an **imitation surface** — it reads as governed, but nothing
instructs it and nothing enforces it; it is governance by appearance.

The inverse case — a gate with no claim, enforcement without a record — is real
and worth noticing, but it is not an imitation surface.

Classifying a repo's own claims against these definitions is a records
exercise: it lands in that repo's `docs/`, not in this template.
